# 后台自动同步

渠道消耗的新快照统一由后台定时同步提供。控制台、用户、渠道及结算页面的“刷新”只重新读取本地数据，不向站点发起同步；打开结算、预览和确认订单也不会先调用远端同步。

## 周期与范围

- 默认周期为约 5 分钟（`SYNC_INTERVAL_SECONDS=300`）。小于或等于零的配置回退为 300 秒，不会持续重复建任务。
- 后台选择未归档且 `collect_enabled=true` 的站点，覆盖所有账号已关联的远端渠道，包括归档渠道以及停用、归档账号的历史渠道。页面筛选、分页和当前登录账号不会缩小自动采集范围；读取结果仍执行原有账号权限。
- 站点 `enabled` 控制分发写入，和采集开关独立。已归档站点或关闭采集的站点不进入新自动批次。
- 调度使用一个可用的超级管理员账号，并保存执行身份；没有有效超级管理员时不创建自动批次。用户无需保持浏览器打开或登录会话在线。

Worker 保持原来的单执行线程。已有自动批次排队或运行时，不再发布重叠批次；长任务或队列积压可能延后下次采集，因此周期不是完成时间承诺。Redis 调度锁减少竞争，PostgreSQL 事务锁覆盖“检查现有批次—创建新批次—提交”全过程，防止锁过期或多个调度者重复入队。每个站点的执行租约继续保护远端操作。

暂时网络错误、限流等可重试读取失败，沿用任务内最多 3 次尝试，前两次失败后分别等待 10 秒和 20 秒。终止失败不会永久阻止后续周期；下个符合条件的周期重新采集。身份、权限、协议错误仍按原校验拒绝，不通过重试伪造成功。已排队的历史同步任务和历史观测保留，前端不再创建或手动重提同步任务。

## 展示与结算

展示和结算使用本地保存的最近成功同步数据。同步尚未成功、缺少有效额度、远端身份不匹配或无法验证美元换算时，消耗保持未知，不能当作 0。真实返回的零值才是零消耗。同步请求失败不会清零上次成功数据或假装更新成功时间。

渠道无需停用即可随时结算。结算继续校验完整的 USD 数据、当前汇率和已有订单基线。若数据不足，需等待后台成功同步后再操作；后端不会在结算请求内补做远端查询。已完成订单中的消耗、金额、汇率和逐目标证据保持冻结。

历史 `UsageFact` 查询、导入、分类统计和趋势使用独立的事实数据，不因这次同步策略变更而删除，也不与渠道累计计数相加。
