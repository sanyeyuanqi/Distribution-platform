# 渠道删除

在“我的渠道 / 渠道管理”打开渠道详情，“平台侧分发明细”右侧的“操作”列提供逐站点“删除”按钮，只删除该行关联的远端渠道。底部“删除渠道”按钮用于删除此渠道的全部可删除分发。确认窗口列出本次操作的站点、远端名称和编号；确认后后台逐站点执行，关闭窗口不会取消已提交任务。可通过详情中的“刷新”查看结果，有任务权限的账号还可在任务详情查看执行过程。

删除针对当前渠道已关联的远端渠道。已删除的分发、尚无远端编号的分发不纳入操作；没有可删除目标或本地渠道已归档时按钮禁用。“远端未找到”仅表示同步时未找到记录，后台会重新读取并核对身份，不据此推断已经删除。

本地渠道、密钥版本、历史消耗和结算记录保留。“归档”用于从默认渠道列表隐藏本地记录，但只有全部远端分发均已确认停用的渠道才可归档。删除不补造无法取得的末次消耗。

归档按整个本地渠道校验，包括所有站点及同站点的密钥分区，不能通过指定部分分发绕过检查。列表和详情根据已保存的远端状态返回 `archive_available` 与 `archive_reason`；单条及批量入口据此禁用不合格项并说明原因。提交时在本地渠道及分发锁内，重新只读核对每个远端的账号权限、渠道身份和状态，全部返回整数 `2`（手动停用）或 `3`（自动停用）后才归档。存在未完成或待核实任务时沿用原有阻止规则。仍启用、状态未知、读取失败、远端未找到、已删除、没有远端编号或身份不匹配都不能凭旧快照归档；暂停站点也不等于停用远端渠道。归档不自动执行远端停用、不清零消耗、不改变历史结算订单，并保存每个远端的核实状态及时间用于审计。

已归档渠道的列表操作栏和详情提供“取消归档”，通过 `POST /channels/{id}/actions` 的 `unarchive` 操作恢复到未归档列表，并刷新分类及分组统计。仅有原渠道管理权限的账号可执行，仍需先处理本地未完成或待核实任务。取消归档只修改本地归档标记，不读取或启用远端，不改变密钥、分发、消耗及结算记录；因此远端暂时不可访问也无需再次核实停用状态。重复提交返回当前渠道，不重复生成审计记录。该操作针对整个本地渠道，不接受部分站点或分发范围。

前端调用 `POST /api/channels/{id}/actions`，提交 `action: "delete_remote"`、确认窗口中的 `distribution_ids`，以及 `confirmation: "DELETE N"`，其中 `N` 为本次目标数量。同站点的 AK/SK、API Key 等分区按各自分发 ID 定位；窗口打开后新增的分发不会自动加入本次删除范围。

服务端再次校验本地归属、任务状态和目标关联，并冻结远端编号、名称与渠道类型。执行时核对远端身份、站点权限与分发关联；不匹配时停止。确认删除请求不会直接删除本地业务记录。

只有明确的远端成功响应才标记为“已删除”。读取失败、权限错误或无法区分原因的 404 保留为待核实，不自动重发删除。响应未知时先只读核实；确认原目标仍存在后，才可通过任务重试明确再次执行。已收到成功响应的删除结果在任务恢复时沿用原确认，不再发送删除。

## 强制删除：本地立即删除，远端异步清理

每条分发记录的“强制删除”在确认后立即永久清理选中的本地记录，并持久保存独立的远端清理任务。这两项在同一数据库事务中完成；远端连接失败、权限不足或历史创建结果不明，不再要求本地渠道继续显示。普通“删除”仍仅删除远端并保留本地历史。

清理任务不依赖已删除的渠道或 Key，仅保留清理所需的站点、远端身份、操作状态与计数。前端单独展示本地删除结果和远端清理进度，不把“本地已删除”显示成“远端已删除”。渠道最后一行删除后详情返回 404 是预期结果，后台清理仍继续。

删除范围包括选中分发及其版本、所属消耗事实、相关任务步骤和历史引用；旧累计采样表已退休。同站点其它分区不受影响，共享任务保留无关步骤。若这是本地渠道的最后一条分发且渠道没有关联结算明细，同时删除渠道、密钥版本、成员指纹和空上传分组；之后同一个 Key 可以作为新上传重新创建。若仍有其它分发，本地渠道及其共用密钥继续供这些分发使用。

提交时检查本地归属、结算明细引用和正在执行的请求。关联结算明细的渠道不能删除最后一条分发；仍在执行的请求也会阻止清理。拒绝时不删除任何本地数据，也不提交远端清理。允许的部分分发清理不会改写结算订单或其中逐目标的历史证据。多行请求的本地清理原子提交，远端步骤独立执行。

接口为 `POST /api/channels/{id}/actions`，提交 `action: "force_delete_async"`、明确且不重复的 `distribution_ids`、`confirmation: "DELETE LOCAL AND QUEUE REMOTE N"` 和 `idempotency_key`。本地渠道已删除后，重试同一请求仍返回原任务；不同载荷不能复用同一请求标识。

“远端清理任务”入口从服务器分页读取持久任务，关闭窗口或刷新页面不会丢失结果。`GET /api/channels/action-tasks` 通过 `offset`、`limit` 查询清理任务，`GET /api/channels/action-tasks/{task_id}` 查询详情，`POST /api/channels/action-tasks/{task_id}/retry` 在后台允许时重试；管理员也可按原有归属范围访问，无需开放整个任务中心。

后台发送前重新校验权限、站点身份、远端编号、名称与类型。正在清理的远端目标会保留占用，采集不会为它重新建立无本地归属的观察记录。没有远端编号且从未发送创建请求时，无需删除远端；历史创建结果不明时可只读按名核实，但不能仅凭同名就删除另一条渠道。

远端暂时连接失败会保留任务并显示重试状态。删除响应未知时先核实，不盲目重发 DELETE；明确成功的结果会持久保存，重启后不重复删除。普通列表缺失或通用 404 不作为成功证据，无法确认时保留“待核实”的清理任务，本地记录不会恢复。强制删除不会注销供应商原始 Key。

旧 `force_delete` 请求及已排队任务仍保留先确认远端、再清理本地的原有语义；新页面使用独立的新请求和确认串。旧 `force_delete_local` 操作仍拒绝。

验证使用隔离测试数据库和模拟远端传输；页面检查拦截全部业务请求，不删除真实渠道。
