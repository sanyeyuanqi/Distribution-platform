# 渠道连通性与消耗同步

当前消耗由 [后台定时同步](AUTOMATIC_SYNC.md) 统一提供，默认约 5 分钟，已有自动批次运行时不会重叠发布。前端没有手动同步操作；列表、详情和结算中的刷新只读取本地快照，结算前也不会主动同步。

渠道管理固定显示当前账号有权查看的渠道，不再提供“仅本人上传 / 授权团队范围”切换。超级管理员可查看全部授权账号，管理员可查看本人及直属普通用户，普通用户只可查看本人。渠道列表、上传分组、渠道分类和消耗导出的接口不再接受范围切换参数；按指定账号查看时仍校验该账号是否在授权范围内。

“标签分组”页签的“操作”列提供“测试”和“查看详情”，测试结果在本地测试窗口查看。并列的“列表详情”页签按平台侧分发逐行展示站点、远端渠道、上传状态、远端状态和消耗金额，同一本地渠道在多个站点或分区上的分发分别显示。支持分类、账号、归档和搜索筛选，分页总数按分发记录计算，包含尚未取得远端编号的上传中或失败记录；“查看详情”打开该记录所属的本地渠道。渠道详情的“平台侧分发明细”提供远端启停、重新上传及删除操作，不显示测试列或逐站点测试按钮。额度列称为“消耗额度”，单行仅显示美元金额（如 `$0.00`），省略“消耗”和“USD”，不另列余额；没有可靠美元金额时显示“—”。原始额度、余额、换算说明及同步状态或错误可通过金额上的提示查看。

标签分组的“总消耗金额”汇总当前已关联平台侧渠道最近取得的累计消耗，按各站点额度比例换算为美元，不按 Key 数量重复计算。列表详情的“消耗金额”使用同一规则计算当前行分发的金额。明确返回的零金额显示为 `$0.00 USD`；没有可用金额时显示“—”，只取得部分金额时显示已同步数量。该显示不改写已核实消耗事实、结算金额或消耗导出。

渠道分类下拉框使用相同的远端金额统计方式，按当前授权范围和归档筛选汇总每个细分类的全部渠道，不受列表分页影响。空分类显示 `$0.00`；存在渠道但缺少可用金额时显示“—”。

从列表打开测试时先刷新渠道信息。模型列表使用当前渠道各已确认上传分发的模型并集并去重，不使用模板全目录或本地渠道的候选模型列表。窗口仅显示模型选择、测试操作和结果，不显示站点或来源选择。渠道级测试结果独立保存，重新打开可恢复最新的渠道级测试。

“测试”打开已上传 Key 的本地测试窗口，可点击“测试该模型”或“测试全部模型”，二者使用同一已上传模型范围。前端统一使用默认短内容，不提供自定义内容输入，也不重用历史自定义内容。后台直接向上游发起小额度推理，不调用接收站点的测试接口。每个模型仅测试实际上传了该模型的分区中的 Key，同一本地 Key 与同一模型跨站点只测试一次，各模型的 Key 范围可以不同。弹窗每行显示一个模型与一把 Key 的结果，各自记录状态、耗时、HTTP 状态码和返回信息，即使消息相同也分行显示。Key 编号使用原本地容器顺序，不展示凭据。进度和成功/失败数量按去重后的“模型 × Key”测试项计算，例如 4 把 Key 测试 1 个模型共 4 项。测试会产生实际模型请求，可能计费；关闭后任务继续，重新打开可查看已有进度。成功不会自动启用远端渠道。

后台定时同步按站点读取已关联远端渠道的累计用量和余额。累计消耗按站点公开 `/api/status.quota_per_unit` 换算为美元：`used_quota / quota_per_unit`，不使用人民币展示汇率 `usd_exchange_rate`。比例必须来自当前受支持版本的有效响应，不硬编码默认值。后台保留原始 quota、十进制美元金额及换算来源，页面至少显示两位小数、最多八位，小于显示精度的正数标明“小于”，不显示成零。没有有效比例时，详情额度列显示“—”，提示中保留未换算原因和原 quota。余额仅在提示中保留，单位取决于上游渠道，未明确币种时保留原值，不标为美元。

缺失数据不会显示为 0；明确返回的零消耗在详情额度列显示为 `$0.00`。这些远端快照不写入已核实消耗事实，不改写历史结算订单；新订单使用最近成功保存且完整有效的快照。同步失败保留上次成功数据，没有成功额度时仍显示未知。2026-09-09 公开核对的 Colin `rc.32-colin` 与 Silicon `fix38` 均返回 `quota_per_unit=500000`；这只是当时的站点值，后续同步重新读取。

本地测试仅接受当前分发已确认上传的 Key：远端编号须与快照一致，且存在当前本地凭据版本的有效上传历史。未上传、上传未确认、远端已删除或未找到的分发不能测试；换 Key 后须先确认该版本已上传。远端已停用或接收站点暂停不影响已上传 Key 的本地测试。需要有效的本地凭据、未归档的本地渠道和已配置的模型。后台采集仍要求现有远端关联。不同渠道可以独立操作，同一渠道的未完成操作须先结束。列表批量返回 `local_test_available` 和 `local_test_reason`，无需读取明文凭据。

前端提交 `POST /api/channels/{id}/actions`。测试使用 `action: "test"`、`test_scope: "channel"` 和一次提交的 `idempotency_key`，不传 `distribution_ids` 或 `site_ids`。单模型传 `model`；全部模型传 `test_all: true` 并省略 `model`，后端冻结已上传模型与对应 Key 的来源计划。渠道接口提供 `local_test_models`、`local_test_available`、`local_test_reason` 和渠道级 `connectivity_test`，前端使用这些字段展示并集及进度。可选 `test_content` 最多 1000 字符，留空时前端省略该字段。提交结果不明时只可明确确认原请求并复用其内容与幂等键，不自动重发；完成后再次主动测试使用新键。旧的单分发测试接口保持兼容。旧手动 `sync_usage` 提交已停用；历史观测和已经入队的任务保留，不从前端重新提交同步。

渠道详情中的 `connectivity_test`、`usage_sync` 返回任务状态、任务编号、时间和不包含凭据的结果说明。本地测试返回 `source: "local"`、`tested_count`、`passed_count`、`failed_count`，以及 `model_results`、`completed_count`、`total_count`、`current_model`、`test_all`、`test_content`。逐模型结果包含状态、耗时、安全说明、HTTP 状态码及 Key 数量；多个 Key 失败时优先显示失败响应的状态码。已完成模型数量只统计完整测试其全部 Key 的模型，中断后的未开始行显示 `not_tested`。一个任务步骤顺序执行并持久化进度，仅全部模型完成才记录最终 `success`；中断或结果不明不会自动重复已发送测试。入队及每次 OAuth 或推理请求前重新校验已上传版本记录与远端关联，同时校验本地归属、账号会话、凭据版本、模型、代理与分区快照、取消状态及执行锁。旧的未发送远端测试任务或缺少上传绑定快照的任务要求重新明确发起本地测试。

每个模型的 `key_results` 分别保存各 Key 的 `key_index`、`status`、`latency_ms`、`http_status`、`message` 和 `provider_message`。表格按模型、结果、耗时、状态码、信息五列展示，状态码独立显示 HTTP 数字，缺失时显示“—”。信息列直接显示该 Key 从官方接口实际收到的错误说明或助手响应文本，不显示“服务器返回”标签；每条消息单独限长，不把不同 Key 的消息合并到一行。前端以纯文本换行显示，不执行返回内容中的 HTML。没有实际响应（例如本地校验失败、网络连接失败）时使用对应的本地说明。旧记录若没有逐 Key 结果，页面提示重新测试，不把聚合摘要放进逐 Key 结果表，也不推算或复制成多条 Key 结果；后端原历史仍保留。

入队时冻结 `test_key_indices`，并初始化每个模型的各 Key 待测试行。每次请求前后持久化对应行；`total_key_count`、`completed_key_count`、`passed_key_count`、`failed_key_count` 与 `current_key_index` 返回逐 Key 进度，原模型统计字段保留兼容。停止或结果不明时，保留已完成 Key 的真实结果，当前 Key 标记未确认或已停止，尚未开始的 Key 标记未测试；不会重放已发送的请求或用其他 Key 的成功结果代替。

渠道范围额外冻结每个来源的上传版本、模型配置和原 Key 编号，并按 Key 与模型生成去重计划。模型依据已关联远端快照中的 `models`；缺少该信息的来源须同步核实，不回退到待上传的本地模型列表。同一测试项的调用参数相同时稳定选择一个来源；若实际调用地址或模型映射冲突，该项显示本地失败说明且不发送请求，其余测试项继续。每次请求前校验冻结来源。渠道范围使用独立任务步骤保存结果，不把整个并集结果归入某个站点的测试历史。

普通服务使用官方地址，Azure 从 Resource 拼接，AWS Claude 使用上传时保存的租户地址，Vertex JSON 先通过 Google OAuth 获取短时令牌。地址和签名请求经过固定目标网络校验，不跟随重定向。测试仅提取有长度限制的服务器消息，保存前过滤请求凭据、私钥、签名、访问令牌等敏感内容，不保存完整响应体或请求头；OAuth 令牌响应不会作为成功消息展示。已配置代理目前会明确提示暂不支持本地代理测试，不会绕过代理直连；音视频、图像等专用模型明确提示不支持轻量文本测试。

功能验证使用隔离数据库及模拟传输。页面检查拦截全部业务接口，不对真实渠道调用模型或执行删除。

远端渠道状态统一按整数解释：`1` 为已启用，`2` 为已停用（手动），`3` 为已停用（自动）；`0`、其他未知值、字符串及布尔值均不视为已停用。分发行返回 `disable_reason: "manual" | "automatic" | null`，仅明确停用时有原因。自动停用不表示渠道已删除，也不能仅凭状态码推断具体故障。已有远端快照可立即用于规范化页面显示，不覆盖失败、待核实、创建中、未找到或已删除等本地状态；后续同步自然更新持久状态。

状态依据：官方 NewAPI `v1.0.0-rc.35` 的 `web/src/features/channels/constants.ts` 第 130–140 行定义 `ENABLED=1 / MANUAL_DISABLED=2 / AUTO_DISABLED=3`；已保存的 Silicon fix41 `index.ec73bdee58.js`（字符偏移 164066）、fix38 `index.87f8a35a5e.js`（163974）、Colin `5151.c047ef84ff.js`（1217）与三野 `6173.d9d85aa367.js`（7021 附近）使用相同含义。仅这些已知值归一化，不将全部非 `1` 值推定为停用。

分发明细把“上传状态”和“远端状态”分开显示。`upload_status` 取该分发最新创建任务（包括重新上传）的 `pending/running/succeeded/failed/needs_review/cancelled/unknown`；`upload_message` 保留该创建步骤的安全错误说明，`upload_is_reupload` 标识重新上传。后续测试、同步、停用、编辑或轮换的失败不改写上传结果；它们的错误仍可由原 `error` 字段显示为操作提示。缺少创建历史的旧记录，只有已确认远端编号及匹配快照时才兼容显示已存在，不从已删除或待核实状态推断上传成功。

`remote_status` 独立返回 `enabled/disabled/unavailable/deleted`，`remote_disable_reason` 为 `manual/automatic/null`。它使用已关联远端快照；创建待核实时也可单独显示已经读取到的远端状态。`deleted` 仅表示已确认删除，卖家列表未找到、没有远端编号或只有未确认的本地删除标记均保持状态未知。旧 `status` 与 `disable_reason` 保留用于兼容原操作判断。所有新增字段均为授权范围内的批量只读投影，不查询密钥，也不改写任务或分发记录。
