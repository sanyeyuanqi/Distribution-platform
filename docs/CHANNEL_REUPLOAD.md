# 失败分发重新上传

渠道详情的“平台侧分发明细”提供逐条“重新上传”。适用于创建失败且没有远端渠道编号的分发；使用后台保存的当前 Key 和目标站点当前已启用的分发模板，沿用原本地渠道、分发记录及远端名称。

提交前需确认目标站点。前端仅提交渠道、分发及请求标识，不读取或传递完整 Key。重复提交同一请求返回同一任务，详情自动更新该条分发的进度与结果。其他站点的分发不受影响。

站点或模板停用、配置不兼容、渠道归档、分发已删除，以及存在执行中或待核实任务时，不能重新上传。已有远端渠道的分发使用现有编辑、启停或更换 Key 功能；重新上传不会覆盖它。

重新上传会建立新任务，保留原任务的配置、错误和发送记录，并阻止已替代的失败创建任务再次重试。发送前重新核对站点、模板、凭据版本和分区；发现同名远端渠道时进入待核实，不自动覆盖或认领。结果未知时不重复发送创建请求。

重新上传仍受目标站点的接口与容量限制。本地通过 128 字符分组校验，不代表远端数据库已支持相同长度；三野的已知限制见 [构建适配说明](SSSVIP_COMPATIBILITY.md)。
