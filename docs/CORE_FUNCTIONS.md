# 当前功能与数据库范围

更新日期：2026-09-11。本文描述当前代码及数据库迁移目标；具体环境是否完成升级，以该环境的迁移版本为准。原需求草案和早期验收记录保留作为历史资料。

## 保留的业务

- 账号登录、固定角色和归属、用户管理及服务端权限校验。
- 站点配置与验证、分发模板、密钥上传、渠道和分发管理、测试、同步、归档及受控删除。
- 用户管理中的分类汇率卡片、分组结算和该用户的结算记录弹窗；独立结算历史页面。
- 控制台渠道消耗合计、分类统计、趋势、来源覆盖，以及消耗事实查询、导入和导出。
- 模板需求与渠道申报容量形成的模型缺口、公告、任务、操作审计、备份和恢复。

渠道消耗统一由 [后台定时同步](AUTOMATIC_SYNC.md) 提供新快照，默认约 5 分钟。已有自动批次未结束时跳过重复调度；前端刷新仅读取本地，结算不触发同步，只使用最近成功保存且通过校验的数据。没有有效观测时保持未知，不当作零。

账号、站点、渠道、分发、凭据版本、任务等支撑表继续保留。此次精简集中在已被当前页面替代的旧账务流程及两个旧接口，不代表移除了系统中所有未使用代码。

## 当前结算数据

`settlement_orders` 保存结算单号、时间、付款方、收款方、分组数、结算消耗和结算金额。`settlement_order_lines` 保存每组当时的身份与标签、汇率版本及百分比、结算消耗 `usage_amount` 和结算金额 `payment_amount`。当前订单不可修改或删除；记录结算不会发起转账，也不再创建独立的付款登记。

首次结算使用已同步的渠道消耗，之后只结算同一远端目标在同一结算关系下的新增消耗。启用中的渠道也可随时结算，无需先停用。金额按消耗乘以分类百分比计算，每项四舍五入至 8 位小数后汇总；0% 可记录为零金额订单。身份、消耗覆盖、汇率变化和重复提交仍由后端校验。详见 [结算订单](SETTLEMENT_ORDERS.md)。

明细的金额列只保留本次结算消耗和金额，但 `site_amounts` JSON 中的逐站点、逐远端目标证据继续保存：累计值、上次基线、本次增量、原始额度、换算依据与观测时间。这些证据用于防止重复结算及识别计数回退、目标重新出现或换算变化，不能因前端不展示累计列而删除。迁移 `7a3d91f0c6b2` 已负责移除冗余的明细累计金额列，本轮不改写这些 JSON 或既有订单。

`discount_versions` 保留分类及细分类汇率版本。`usage_facts` 保留历史消耗事实，供分类、趋势、来源覆盖和导入导出使用；它与当前远端观测消耗及订单明细是不同数据来源，不应相加。

## 退休的空表与接口

迁移 `4f8b27c93a10` 位于 `7a3d91f0c6b2` 之后，移除以下 9 张旧表及其对应模型和接口。实施前已只读确认本地业务库中的这 9 张表均为空；其他环境仍须通过迁移的非空检查。

| 表 | 已退休用途 |
| --- | --- |
| `bills` | 旧草稿、待支付和已支付账单 |
| `bill_lines` | 基于消耗事实的旧账单计价明细 |
| `settlement_claims` | 旧账单对消耗事实的占用 |
| `payments` | 独立人工付款和交易登记 |
| `payment_rules` | 独立支付币种换算规则 |
| `attachments` | 旧账单付款凭证附件 |
| `adjustments` | 已支付旧账单的调整记录 |
| `model_targets` | 独立配置的旧模型目标清单 |
| `usage_samples` | 旧累计采样、增量和回退记录接口 |

旧 `/bills` 页面、旧账单预览/确认/作废/支付/调整/附件接口、`/payment-rules`、`/model-targets` 和 `/usage/samples` 不再提供。模型缺口继续读取分发模板的 RPM/TPM 需求；渠道同步继续保存远端观测，不依赖上述采样表。

保留的结算接口为 `GET/POST /discounts`、`GET /settlements/groups`，以及 `/settlement-orders` 的预览、创建、列表和明细接口（均使用 `/api` 前缀）。分组响应直接返回当前订单状态 `settlement`，不再附带旧账单 `financials` 或嵌套的 `order` 投影。用户列表的 `full` 和 `management` 参数均返回当前管理表需要的字段，不再计算旧账务汇总。

## 迁移与历史保护

升级在同一 PostgreSQL 事务内按固定排序对全部 9 张表取得排他锁，随后逐表检查是否有记录。任意一张非空，整个升级在删除任何表之前拒绝执行；不自动清空、不自动转换旧账单。检查通过后按外键依赖顺序删除，未使用 `CASCADE`。遇到旧数据应停止升级并制定单独的数据保留方案。

降级只重建与旧迁移一致的空表、索引和约束，不恢复已退休功能的应用代码。既有数据库迁移与历史设计文档保留。备份工具仍兼容归档中可能存在的旧私有附件文件，本轮不清理这些文件或备份。

渠道本地删除仍校验权限和并发任务；关联结算明细的渠道不能通过删除最后一条分发而被移除。允许的分发删除仅清理其自身范围内的消耗事实及运行记录，其他分发和冻结订单明细继续保留。
