# 前端需求驱动的系统优化

第一轮完成日期：2026-09-11。以下测量与测试数量记录当时的加载性能、列表请求和统计查询优化，不是后续精简版本的重新测量。

后续已增加功能与数据库精简：迁移 `4f8b27c93a10` 在全部 9 张退休表为空时移除旧账单、支付、独立模型目标及累计采样结构；任意非空则拒绝升级。当前保留范围与保护规则见 [CORE_FUNCTIONS.md](CORE_FUNCTIONS.md)。

## 已完成的调整

| 部分 | 调整前 | 调整后 |
| --- | --- | --- |
| 页面加载 | 所有页面随入口脚本加载 | 路由按需加载，提供加载状态和失败后的刷新入口 |
| 静态资源 | JavaScript/CSS 未压缩传输 | Nginx 根据浏览器请求启用 gzip，保留带版本资源的缓存规则 |
| 用户管理 | 自动读取全部账号页，随后在浏览器分页；请求旧账务汇总 | 每次读取 50 条，服务端搜索和分页；`view=management` 只计算管理表需要的统计 |
| 渠道管理 | 列表详情页仍会读取分组列表；浏览器分页叠加后端批次 | 只请求当前视图；使用统一的服务端分页组件 |
| 搜索 | 输入变化即请求 | 用户、渠道搜索在停止输入 250 ms 后请求，新条件回到第一页 |
| 数据请求 | 旧读取继续执行，切换范围时可能暂存旧数据 | 按路径和会话隔离；取消被替代的读取，忽略迟到的结果 |
| 结算历史 | 单独维护一套读取状态 | 历史页面、用户记录弹窗和明细复用公共请求模块 |
| 控制台 | 读取全部历史消耗事实后逐条统计 | 数据库汇总分类、单位、覆盖数与 14 天趋势；只返回汇总桶 |

用户精确查找使用 `user_id`，因此账号不在当前页时，既有结算深链接仍能使用。第一轮保留默认完整视图，新增管理视图避开旧账务查询；后续精简将 `full` 和 `management` 统一为当前用户管理需要的字段，均不再返回旧账务或分类汇总。

公共 `api` 仍支持原有调用方式，并增加可选取消信号。`useData` 的 `refresh` 和 `setData` 引用保持稳定，避免轮询和弹窗效果因回调身份变化而重复执行。退出或更换会话后，旧请求不能覆盖新会话的 CSRF 信息，也不能用迟到的 401 将新会话退出。

## 测量与验证

测量来自本地生产构建与 `localhost:8080` 的实际响应，KB 使用十进制。以下为入口脚本大小，不是整个页面的总资源或加载耗时。

| 指标 | 调整前 | 调整后 |
| --- | ---: | ---: |
| 入口 JavaScript 原始大小 | 733,225 字节 | 482,712 字节 |
| 请求 gzip 后实际传输大小 | 733,225 字节（未压缩） | 176,664 字节 |

- 第一轮用户管理测试验证轻量视图与原完整视图的公开字段相等，至少省去 3 次历史汇总查询；批量统计不会随每页账号数逐行增加请求。后续精简后两种视图统一，原查询差值仅作为第一轮记录。
- 控制台测试增加 250 条历史事实后，查询次数和返回汇总桶数保持稳定，汇总金额与旧算法一致；不读取历史证据文本、渠道密钥、站点令牌或任务大快照。
- 149 项相关后端测试通过，包括角色权限、当前消耗、历史归属、结算订单、金额精度、分页、字面搜索字符和上海日期边界。
- 33 项前端测试通过，包括取消、乱序响应、会话切换、现有金额计算和模型排序。TypeScript、生产构建、相关格式及静态检查通过。
- 本地 API、worker 和 web 已更新并通过启动检查。浏览器核对了用户搜索、空/有记录用户的结算弹窗、订单明细、汇率卡片、结算深链接、渠道两种视图及其搜索和详情；控制台、站点、分发模板、模型缺口、公告、任务、审计和结算历史页面均正常打开。
- 实际访问日志确认用户列表请求携带 `view=management&offset=0&limit=50`，详情视图搜索只请求 `/channel-distributions`，没有附带分组列表请求。

## 保持的约定与边界

第一轮性能优化没有新增迁移；后续已跟进上述空表退休迁移。两轮都保留现有结算订单中的金额、消耗、汇率和增量基线；金额仍采用精确十进制计算，未知消耗不会伪装成零。

全局渠道消耗仍按授权范围内的 `(site_id, remote_id)` 去重，保留归档渠道、缺失观测和单位换算规则。管理员团队范围与普通账号权限不变。读取统计不触发远端同步或创建结算单。

当前远端消耗仍需检查各远端渠道的观测，因此其工作量随可见远端渠道数增长。历史统计改为数据库聚合，仍会执行实际汇总，并非缓存后的常数时间查询。真实部署的加速幅度还取决于数据规模、硬件和网络；没有将上述构建大小换算为页面耗时提升百分比。
