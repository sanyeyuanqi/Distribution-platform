# 模型 RPM / TPM 缺口

模型缺口只从分发模板读取需求，无需再填写独立的目标模型清单。按“渠道分类 + 服务类型 + 原始模型名”汇总，各维度分别计算：

`缺口 = max(模板需求总量 − 渠道已申报总量, 0)`

例如两个站点同类型、同模型的 RPM 需求分别为 300 和 200，现存渠道已申报 RPM 为 100 和 150，RPM 缺口为 `500 − 250 = 250`。TPM 使用自己的需求和申报值独立计算，不从 RPM 估算 Token 数。

## 需求

- 使用未归档站点上的所有现存模板。模板和站点的分发开关控制新上传，不清除已填写的需求。
- RPM 来自 `model_rpm_requirements`，TPM 来自 `model_tpm_requirements`，只包含模板已选择的模型。
- 某个维度完全未填写时表示“未设置需求”，不是零需求。
- AWS Bedrock 与 Claude 代理、Azure GPT 与 Claude、Google AI Studio 与 Vertex 等服务类型分别统计。模型映射不改变原始模型的需求归属。

## 现存渠道总量

- 遍历所有未归档站点与未归档本地渠道，至少有一条带确认远端 ID、仍然存在的分发记录才计入。待创建、创建失败、删除或远端缺失的记录不计入。启用与停用的现存渠道都属于库存总量；测试时间不影响该统计。
- 同一本地渠道的各站点、各分区所包含的模型取并集，每个模型只计一次渠道配额。不按站点数、分区数或 Key 数量相乘。
- 来源为上传时记录的 `account_info.rpm/tpm`。历史渠道可回退到一致的冻结申报值。明确填写的 `0` 是已知零值，缺失、非法或相互矛盾的历史值是未知。
- 配额是渠道整体申报值，展示该渠道对某个模型的申报容量；不代表多个模型同时调用时各自均能独占整条渠道配额。不同本地渠道也不保证对应独立上游账户，统计不解密或探测密钥。
- `rpm_limit` 是渠道限流设置，消耗金额是累计用量，都不作为 RPM / TPM 容量。当前适配器没有自动读取上游逐模型 RPM / TPM 配额的能力，不根据渠道数量或模板需求生成配额。
- 已发现但未接管的远端渠道缺少可靠的本地服务类型和配额资料，单独返回其数量，不虚构供给。

部分渠道未填写配额时，已申报总量仍可汇总，但正缺口标注“估算”：它是按已知数据算出的缺口上限，不是完整容量的精确差额。若已知总量已经满足需求，缺口仍为零。RPM 与 TPM 的数据完整性独立判断。

## 页面和接口

页面列出至少填写一项需求的模型，按 RPM 缺口从大到小排序，显示类型、模型名、缺口 RPM、缺口 TPM；缺口仅显示数值，不提供展开明细。保留未设置需求的标识和估算列标题。完全未设置需求时提示前往分发模板填写。页面可见时每分钟刷新一次，手动刷新只重新读取统计，不修改模板或渠道。

所有已登录账号可查看平台级分类、模型汇总；接口不返回渠道 ID、站点明细、所有者、密钥、备注或具体账号信息。只有超级管理员看到前往分发模板设置需求的入口，模板编辑权限不变。

整数配额使用十进制字符串传输，避免大数在浏览器中损失精度。没有需求的单位，`required_*` 和 `gap_*` 为 `null`；`supplied_*` 是已知申报值合计，未知渠道数量另列。

旧 `ModelTarget` 模型与 GET/PUT `/model-targets` 接口已移除。迁移 `4f8b27c93a10` 仅在退休表均为空时删除 `model_targets`；不影响模板需求、渠道申报容量或本页计算。详见 [当前功能与迁移范围](CORE_FUNCTIONS.md)。
