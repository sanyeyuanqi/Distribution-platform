## 接口契约

- 使用管理访问令牌，核对 `/api/user/self` 的身份、启用状态与管理员角色。该构建的公开渠道页面按管理员角色授权，不套用官方新版的独立渠道权限字段。
- 读取 `/api/channel/`、`/api/channel/models` 和 `/api/group/`。实际身份、列表和元数据读取均已确认成功。
- 创建使用 `POST /api/channel/`，直接请求带尾斜杠的规范路由，避免 HTTP 307 重定向；编辑和启停使用 `PUT /api/channel/`；删除使用 `DELETE /api/channel/:id`。启停只提交 `id`、`status`。
- 已用管理身份只读核对不存在渠道的详情响应：HTTP 200、`success: false`、`message: "record not found"`、`data: null`。仅该精确构建可使用此响应确认不存在；一般 HTTP 404 或权限错误不能作为已删除证据。
- `setting`、`settings` 使用 JSON 字符串，代理保存在 `setting` 中；模型和分组使用逗号分隔字符串。每个分组必须来自站点返回的可用分组，不能假定存在 `default`。
- 按用户设置，此构建在本系统中的分组名称合计上限为 **128 个字符（含逗号）**，按 Unicode 字符而非 UTF-8 字节计数。前端选择、模板启用、上传预检及实际发送共用此限制；不截断名称、不自动删除已选分组。
- 128 是本系统的校验上限，并不表示已修改或验证远端数据库容量。已核对的官方 NewAPI `model/channel.go` 中 `Group` 定义为 `varchar(64)`，且三野曾对 85 字符分组返回 `Error 1406 (22001)`。站点若仍拒绝字段长度，需由站点提高容量或减少分组；错误提示与本地超过 128 字符的提示分开，避免把远端拒绝误报为超过本地上限。
- 核对的业务类型为 `1、3、14、20、24、33、41`。多密钥沿用公开表单的 `multi_to_single`、随机选取与 `key_mode=replace` 契约；Vertex API Key 的公开表单仅允许单密钥创建，因此同一本地容器中的此类密钥分别创建远端渠道，服务账号 JSON 及其他类型仍可使用远端多密钥渠道。
- 消耗美元值按 `used_quota / quota_per_unit` 计算。站点返回的 `usd_exchange_rate` 仅用于人民币显示，不额外乘入美元消耗。
- 不套用仅对官方发行版核实的 Bedrock SDK 绕行策略，也不把未核实的 Vertex Claude API Key 转发能力标为支持。

公开客户端证据和摘要保存在 `.local/reference/sssvip/contract-evidence.json`。公开来源为该站点的[入口脚本](https://sssvip.shop/static/js/index.585bc7de3f.js)和[渠道管理脚本](https://sssvip.shop/static/js/async/6173.d9d85aa367.js)。前端指纹用于识别已核对的客户端契约，不等同于服务端源码身份或真实写入验收。

初次接入时的真实站点核对仅执行读取，创建、编辑、删除、启停及构建变化使用模拟请求回归。随后修复创建路由时，按用户报告恢复了一条原有失败任务：规范路由不再返回 307，站点返回了分组字段超长的明确业务拒绝，未取得远端渠道编号。该任务沿用原稳定名称，并在发送前核查同名渠道，未创建额外测试渠道或发起模型推理。已知分组超长错误映射为固定说明，其他远端业务错误继续泛化，不回显原始响应。接入修正不自动开启站点分发，也不自动修改渠道分组或创建模板。
