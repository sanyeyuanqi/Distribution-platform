# 渠道模板与简化上传

超级管理员为每个站点、每个接入类型配置分发模板。接入大类固定为 AWS、Anthropic、OpenAI、Azure、Google、OpenRouter、OpenCode，按此顺序显示。用户选择分类并按内置格式粘贴密钥，即可按各站点模板分发。

“分类与格式”管理入口已经移除，`/catalog` 跳转至分发模板。分类和凭据规则由代码内置，不能从管理接口新增或编辑定义。模板选择“渠道分类”后自动匹配该细分类的“凭据格式”，优先匹配已启用格式；只有一个格式时直接只读展示，存在多个格式时才提供对应选项，不能选空。分类与格式并排显示，下方展示同一内置定义提供的填写示例和说明，切换分类时同步更新；上传者不需要查看协议编号或填写格式 JSON。

模板共用渠道管理“全部分类”的服务细分类和搜索菜单：AWS Bedrock、AWS Claude 代理、Anthropic 官方、OpenAI、Azure OpenAI、Azure Claude、Google AI Studio、Vertex AI Gemini、Vertex AI Claude、OpenRouter、OpenCode。表单必须选择具体分类，不提供“全部分类”，不显示消耗金额。切换分类会重新选择对应格式；新模板同时重置接收模型、需求量与映射。已创建模板的站点、分类及格式固定。

初始化补齐固定类别和内置格式，保留历史 ID、接入归属及密钥解析规则。已有模板清除非状态的渠道默认参数与模板代理，并更新模板版本；接收模型、分组、备注和启用状态保留，历史渠道、密钥与冻结任务快照不重写。旧 Azure API Key 模板归入 Azure GPT，新上传使用资源名复合凭据，旧渠道继续使用原来的裸 Key 解析。现有模板的接收模型与上传 Key 模型取交集的规则保持不变。

## 配置模板

新建站点时，系统按当前启用的内置分类与接入类型自动创建停用模板；完整目录生成 11 份，AWS Bedrock 的两种密钥共用一份。模板使用站点默认分组（新站点为 `default`），接收模型留空，创建后的渠道状态默认为停用。管理员在分发模板中配置接收模型后，再按需启用模板及站点分发。模板与站点同时保存；连接验证失败时仍保留停用模板。编辑、重新验证站点或重启服务不会重新创建已删除的模板，也不会覆盖已有模板配置。

OpenAI 与 Azure OpenAI 模板的内置候选模型使用 2026-09-10 用户提供截图合并后的 26 个模型，按完整模型 ID 去重；简称和带日期的版本分别保留。新建模板不再从其他模板收集历史 OpenAI 大列表，Azure Claude 等其他分类不受影响。各分类模型在合并候选及已选项后统一按官方 API 发布日期从新到旧显示，未知日期置末尾，同日保留原顺序；列表标签和模型选择同步排序，详见 [模型显示顺序](MODEL_RELEASE_ORDER.md)。编辑已有模板时保留其已配置模型及需求、映射，保存配置仍由管理员决定。

1. 站点管理中选择正确接入方式并验证。官方 NewAPI 使用「NewAPI 标准渠道接口」，Silicon 和 TCP Red / Colin 使用各自适配器。填写管理账号的系统访问令牌和用户编号，不能用推理令牌代替。
2. 选择目标站点、渠道细分类与对应凭据格式。模板名称可选。AWS Bedrock 在一个输入框内接受 `AccessKeyID|SecretAccessKey` 或一个 `APIKey`，允许混合批传，按鉴权类型建立远端分区。Region 可省略：官方短期 API Key 优先读取签名地区，其余自动补全 `us-east-1`；需要其他地区时写 `AK|SK|Region` 或 `APIKey|Region`。Claude 代理使用 API Key 和真实的 HTTPS `*.api.aws` 主机地址，由上传者提供本批地址；它是租户专属地址，不能根据 API Key 猜测。Vertex AI 支持服务账号 JSON 或 API Key。
3. 选择创建后的渠道启用 / 停用状态。默认创建停用渠道，选择启用还要求站点已验证启停权限。模板不再提供 API 地址、组织 ID、API 版本、默认上传方式等设置；协议参数由系统固定，上传方式默认批量，上传者仍可选择单条上传。Azure GPT 按行填写 `Resource|ApiKey|ApiVersion`，自动生成 `https://{resource}.openai.azure.com`；Azure Claude 按行填写 `Resource|ApiKey|ApiVersion`，兼容旧的两段格式；第三段仅保存在凭据中，Claude 接口不使用 Azure API 版本查询参数。系统自动生成 `https://{resource}.services.ai.azure.com/anthropic`。每条凭据可以属于不同资源，远端渠道只收到 Key 段，资源与版本分别写入对应渠道参数。
4. 接收模型支持搜索和全选，每模板最多 200 项。每个选中的模型可分别填写 RPM（每分钟请求数）和 TPM（每分钟 Token 数）需求量：RPM 为 1–1,000,000 的整数，TPM 为 1–1,000,000,000 的整数，各自留空表示未设置。两项独立保存，单独清空一项不会清除另一项。取消选择模型会同时清除它的两项需求和模型映射，搜索不会改变已填写的值，保存草稿或启用模板后均可重新打开查看。原生 NewAPI、Silicon `fix-36` / `fix-38` 和 Colin `rc.32-colin` 支持合法自定义模型；这些版本的模型目录是建议列表，不代表完整的上游模型范围。旧版 Silicon 仍按已验证的模型集合限制。模型去除首尾空白、按首次出现顺序去重；200 项上限在去重前校验，单个模型名称不超过 200 个字符。
5. 原“手动添加模型 ID”区域改为模型映射，支持可视化逐行编辑和 JSON 对象编辑。原始模型可以选择已有模型，也可以填写新的模型 ID；替换模型填写实际调用的模型 ID，例如 `{"gpt-3.5-turbo":"gpt-3.5-turbo-0125"}`。点击“应用映射”后，新的原始模型自动加入并选中到上方接收模型，可继续设置 RPM / TPM；替换模型不会作为额外接收模型重复加入。接收模型卡片展示对应替换模型，并提供删除按钮，删除会同步清除该模型的映射和两项需求。内置候选仍可重新选择。可添加或删除多条映射，同一原始模型只能有一条；留空、重复、无效配置或应用后超过 200 个接收模型时不能保存，不会部分加入。没有映射时继续使用原有转换规则。模板还保留目标站点、类型 / 上传分类、名称、创建后渠道状态、接收模型及其 RPM / TPM 需求量、目标分组和默认备注。自定义优先级、权重、异常处理、状态码映射、默认代理、渠道 RPM 保护、号况等不从模板配置；服务端统一使用固定默认规则。上传者仍可在上传页高级选项中设置本批密钥的号况和代理。
6. 映射中的原始模型尚未选入接收模型时，映射下方显示黄色提示，列出缺失模型和数量。点击“添加缺失模型”可一次加入并选中这些原始模型，同时应用映射；已有模型不重复添加，已有 RPM / TPM 保留。可视化和 JSON 编辑均支持，映射内容不完整或无效时需先修正。没有缺失模型时，映射修改继续通过“应用映射”确认。
7. 保存草稿或保存并启用。站点分发开关与模板开关都启用时才接收新上传。

每站点、每分类一份模板；AWS 允许 Bedrock 与 Claude 代理各一份，Azure 允许 GPT 与 Claude 各一份，模型、路由组、启用状态分别设置。其他分类的启用模板仍使用相同内置格式。历史 AWS AK/SK 和 API Key 模板保持原引用，新上传入口统一解析两种凭据；已有渠道补分发继续保留原凭据定义。Google 模板选择 Gemini（type 24）或 Vertex（type 41）格式；Vertex 的 Gemini / Claude 用途由模型配置区分，不能混用两种协议的密钥。OpenCode 使用 Anthropic 兼容格式（type 14）和固定官方地址 `https://opencode.ai/zen`，不需要手工填写地址。

模板的「目标渠道分组」支持多选，一条渠道可同时属于多个远端分组，不会按分组重复创建渠道。最多选择 32 个分组，名称和逗号合计不能超过 160 个字符。后端去除名称首尾空格、按首次选择顺序去重，继续使用逗号分隔字符串保存及发送，例如 `default,vip`；单组选项和历史任务快照保持兼容。每个所选分组都必须在站点已验证的分组中，远端写入前再次核对。已失效的分组可保留在草稿中，修正后才能启用。站点本身的默认分组仍为单选。

Claude 代理的 API 地址由上传者填写，只能是无路径、端口、账号、查询和锚点的真实 HTTPS `*.api.aws` 主机，并随任务冻结。模板中不保存该地址。Bedrock Mantle、Bedrock Runtime、Claude Platform on AWS 属于有专用路径或工作区要求的官方接口，不能作为普通租户代理填写。详见 [AWS 接入协议](AWS_UPLOAD_PROTOCOL.md)。Azure Claude 使用 Microsoft Foundry 官方 Anthropic 接口；模型名称必须对应该资源中的部署名称，配置接收模型不会自动部署模型。协议参考：[Anthropic 官方 Foundry 文档](https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry)、[Microsoft Foundry Claude 文档](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/how-to/use-foundry-models-claude)。

API 密钥由上传者提供，不存入模板。上传者填写的代理单独加密保存。修改模板只影响后续任务，已分发渠道及历史任务快照保持原值。

模型需求分别以模板字段 `model_rpm_requirements` 和 `model_tpm_requirements` 保存，例如 RPM 为 `{"claude-opus-4-6": 300}`，TPM 为 `{"claude-opus-4-6": 2000000}`。仅超级管理员可随模板创建或修改；每项必须对应当前选中的模型，数值严格使用正整数。未填写的模型不出现在相应字典中，旧模板新增的 TPM 默认为空字典，原有 RPM 保留。PATCH 显式提供某字段时替换该类需求；未提供的字段保留已有值，若同时减少接收模型则清除两类需求中对应的旧值。两字段记录需求目标，不是实际吞吐量或渠道限流参数，不写入远端渠道。模型缺口页面汇总这些需求，再减去跨站点去重后的渠道已申报容量，不再单独配置目标模型或按近期测试次数判断覆盖；计算口径见 [模型缺口](MODEL_CAPACITY_GAPS.md)。

自定义模型映射单独保存为模板顶层字段 `model_mapping`，旧模板默认为 `{}`。PATCH 未提供时保留已有映射，显式 `{}` 清空，减少接收模型时清除对应映射。模型 ID 必须为非空字符串，不含逗号或控制字符，且不超过 200 个字符或 255 个 UTF-8 字节。映射只应用于实际分发交集中的原始模型，自定义值优先于系统自动转换；它不会扩大上传 Key 的模型范围，也不会改变凭据类型或接入协议。映射随有效渠道配置冻结到任务中；修改模板不改写已有远端渠道与历史任务。

## 用户上传

默认流程：选择分类 → 确认自动标签与可选设置 → 粘贴密钥 → 提交，后台自动检查并按模板分发。页面顶部显示七类及可用密钥类型，左侧为自动标签和高级选项入口，右侧为密钥说明、输入与单密钥 / 批量切换。目标站点由后台确定，不展示站点列表。旧手动上传页面继续跳转到简化上传。同一批标签的有效密钥合并为一个本地渠道；每个站点按认证方式、Azure 资源和版本、逐条备注及代理分区，兼容的多把密钥创建一个随机分流的远端多密钥容器。历史单密钥渠道及旧高级接口不自动重组。

- 文本密钥：单密钥只接受一条；批量每行一条完整凭据，AWS 各部分用 `|` 分隔。
- AWS 切换 Bedrock / Claude 代理会清空旧凭据、地址和高级设置，分别展示对应模板的模型范围。Bedrock 不发送代理 API 地址；Claude 代理不发送到 Bedrock 模板。混合 Bedrock 上传保持一个本地渠道，AK/SK 与 API Key 分别分发为两类远端渠道。更换密钥时须保持原顺序、数量及认证分区。
- JSON 密钥：单密钥支持整个多行对象；批量支持对象数组、连续粘贴多个美化对象，以及 JSON 和每行纯 API Key 混合输入。Vertex 要求 `project_id`、`client_email`、`private_key`，额外字段保留。JSON 压行为规范格式后去重；错误或未闭合的 JSON 不会被静默丢弃，列表不展示凭据片段。Vertex Claude 的 API Key 还需要目标版本明确支持。
- 自动标签由服务端生成，预览与提交使用同一批次令牌，新建分组使用该标签；成功后生成下一批标签。修改已提交但响应不确定的内容时视为新批次，直接重试则复用原批次与幂等标识。
- 高级选项弹窗提供可搜索、滚动的复选框列表、全选/半选状态和已选数量。Claude 只展示指定的九个模型与当前模板模型的交集；其他供应商的模型范围保持原值。默认勾选当前可显示的全部模型，搜索只筛选显示，不改变选择。显式清空不允许提交，每批最多选择 200 个模型；默认范围超过 200 个时须先缩小范围。上传页始终提交本批 Key 的模型范围，包括未打开高级选项时的默认全选，以便后续补分发和重建沿用原选择。取消或关闭弹窗不应用修改。
- 实际分发模型为“当前站点模板接收模型 ∩ 上传 Key 的模型范围”，按模板顺序保留。上传范围中不被某站点接收的模型会被忽略；该站点交集为空则跳过，所有站点都没有交集则不创建上传任务。历史未携带模型范围的上传继续沿用模板全部模型。
- 上传页保留七个分类，但没有可用接收模板的分类置灰，鼠标和键盘均不可选。可用性以后台 `ready` 校验结果为准，已有模型数据或模板数量不代表可以接收。AWS 只要有一个子类型可接收，分类即可选；Bedrock 与 Claude 代理分别判定、分别置灰，默认选可用子类型。
- 地址预选或刷新后的分类/格式失效时，自动切换至首个可用项并清空旧密钥和高级设置，避免跨渠道误传；全部不可用时不选中任何分类且禁止新提交。已提交但响应不确定的请求仍保留原冻结内容和幂等标识，可继续核实重试，不被自动切换覆盖。AWS Bedrock 与 Claude 代理的模型范围仍按接入类型隔离。

- 入库存（备用，暂不上线）：勾选后仍按模板分发，但强制以停用状态创建渠道，不参与调用；重试、模板任务重建和未知结果核实均保留该状态。未勾选则沿用各站点模板状态。
- 号况申报只发送用户编辑过的字段，0、否及显式清空均按实际值处理。备注和 SOCKS5 / HTTP(S) 代理支持一行整批共用或按原始密钥记录逐条对应；去重前完成绑定，备注留空使用模板默认备注，代理留空表示不使用代理。代理仍加密保存，不显示在提交结果中。
- RPM 保护默认关闭。页面不选择目标站点；只有用户切换了可用格式时才提交格式编号。

Claude 展示顺序固定为：`claude-haiku-4-5-20251001`、`claude-opus-4-6`、`claude-opus-4-7`、`claude-opus-4-8`、`claude-sonnet-5`、`claude-fable-5`、`claude-opus-5`、`claude-sonnet-4-6`、`claude-fable-5-1`。现有两个站点的 AWS、Anthropic、OpenRouter、OpenCode 模板均统一配置这九个名称。未设置自定义映射的模型继续自动转换 OpenRouter 的供应商前缀 / 版本点号、OpenCode Haiku 的日期别名，并冻结到分发任务中。模型交集仍按上传页中的原名称计算。配置模型名称不会改变接入协议，实际调用仍取决于上游接口支持范围。
- 内部预览仍校验密钥、站点能力和模板版本；校验失败时，红色提示框汇总无法分发的具体原因，包括整批错误、站点接收问题和带行号的凭据错误，逐行明细仍保留。已有密钥命中归档渠道、已强制删除的本地分发、已删除的远端分发或配置差异时分别说明，不再统一提示“配置不同”。提示不包含完整密钥、代理或后台模板的具体配置值。校验失败不创建任务；提交保持幂等，网络错误后的重试不会使用新的任务标识重复创建。
- 提交成功只显示后台处理提示，不自动打开任务详情。管理员在“我的渠道”查看结果；有任务权限的账号可主动查看进度。

号况作为本地申报保存，不会改写真实账户余额，也不等于执行限流。RPM / TPM 配额申报和 RPM 保护是独立设置。

多密钥的供应商余额仍各自独立，不能宣称合成一个上游账户余额；本地按远端分发汇总实际消耗。渠道详情显示总密钥数量，各远端记录显示认证分区与成员数；测试、消耗同步及删除均按具体分发 ID 操作。整组换 Key 保留旧加密版本，要求完整提交相同数量并维持原顺序及分区；重试以被冻结的分区及成员指纹校验，不能将另一组密钥写入当前远端渠道。

## 接入范围

官方版本覆盖 2026-06-08 至 2026-09-08 发布的全部 26 个标签（v1.0.0-rc.11–35 及 rc.19-i18nfix.2），并保留 v0.13.2，共 27 个明确版本，详情见 [NewAPI 兼容性](NEWAPI_COMPATIBILITY.md)。后台自动按各版本选择权限校验、启停接口及渠道类型能力。验证及写入前核对版本；未知版本不自动视为兼容，后续需核对差异并补充契约测试。

- 原生 NewAPI：完整渠道参数、固定类型凭据、自定义模型及代理；没有本项目的原生 RPM 保护和号况执行字段。
